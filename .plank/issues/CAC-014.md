# Add version compatibility tests for Data URL and legacy formats

## Description

CAC-009 introduced 3-path format detection in `_loads_any`. We need explicit
tests that verify all read paths work correctly, including cross-version
scenarios (e.g. v0.6.x data read by v0.7.0 code).

### Test matrix

| Write format                     | Read by       | Expected |
|----------------------------------|---------------|----------|
| DURL, uncompressed               | v0.7.0        | ✅ pass  |
| DURL, compression=zstd           | v0.7.0        | ✅ pass  |
| DURL, compression=zlib           | v0.7.0        | ✅ pass  |
| DURL, bytes type (octet-stream)  | v0.7.0        | ✅ pass  |
| Legacy raw JSON bytes            | v0.7.0        | ✅ pass  |
| Legacy zstd-compressed bytes     | v0.7.0        | ✅ pass  |
| Legacy zlib-compressed bytes     | v0.7.0        | ✅ pass  |
| Legacy raw bytes (bytes type)    | v0.7.0        | ✅ pass  |

Tests should inject data directly via `cache.cache.set()` to simulate
legacy-format stored values, then verify `cache.get()` reads correctly.

Also test `_dump_any` output format assertions:
- Starts with `data:application/json;base64,` (or `octet-stream`)
- With compression, contains `compression=zstd` or `compression=zlib` parameter
- Round-trips correctly through `_loads_any`

## Acceptance Criteria

- [ ] Test file: `tests/test_version_compat.py`
- [ ] All 8 read-path combinations pass
- [ ] `_dump_any` output format assertions
- [ ] Cross-read: compressed writer + uncompressed reader (DURL-aware)
- [ ] Cross-read: uncompressed writer + compressed reader (DURL-aware)
