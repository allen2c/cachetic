# Expand CacheProtocol with `exists` and `clear` methods

## Description

`CacheProtocol` currently only defines `set`, `get`, `delete`. Add two
commonly needed operations: `exists` (key lookup) and `clear` (flush all).

### Updated protocol

```python
class CacheProtocol(typing.Protocol):
    def set(self, name: str, value: bytes, ex: int | None = None, /) -> None: ...
    def get(self, name: str, /) -> bytes | None: ...
    def delete(self, name: str, /) -> None: ...
    def exists(self, name: str, /) -> bool: ...
    def clear(self) -> None: ...
```

### Backend implementations

| Backend       | `exists`                          | `clear`                        |
|---------------|-----------------------------------|--------------------------------|
| DiskCache     | `key in self._cache`              | `self._cache.clear()`          |
| Redis         | `self._client.exists(name) > 0`   | `self._client.flushdb()`       |
| MongoDB       | `self.col.count_documents(...)>0` | `self.col.delete_many({})`     |
| PostgresCache | `SELECT 1 WHERE name = ?`        | `DELETE FROM {table}`          |

### Backward compatibility

- Third-party `CacheProtocol` implementors that lack `exists`/`clear` will
  get a type error at check time but won't break at runtime unless called.
- `Cachetic` class exposes `exists()` and `clear()` as new public methods.
- Existing API unchanged.

## Acceptance Criteria

- [x] `CacheProtocol` defines `exists` and `clear`
- [x] All three backends implement `exists` and `clear` (Postgres in CAC-010)
- [x] `Cachetic.exists(key)` delegates to backend (with prefix)
- [x] `Cachetic.clear()` delegates to backend
- [ ] Tests for `exists` and `clear` on each backend (deferred — integrated tests planned)
