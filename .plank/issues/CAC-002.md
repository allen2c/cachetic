# CAC-002: MongoCache — Deduplicate createIndexes calls

## Description

`MongoCache.__init__` calls `col.create_index("name", unique=True)` unconditionally
on every instantiation. When multiple `MongoCache` instances target the same collection
(or when the same collection is opened repeatedly), this sends redundant `createIndexes`
commands to the server (~130–230ms each on CosmosDB).

Introduce a module-level set tracking which `(database, collection)` pairs have already
had their indexes ensured. Skip the `create_index` call for pairs already in the set.

## Acceptance Criteria

- [ ] A module-level `_ensured_indexes: Set[Tuple[str, str]]` tracks ensured `(db, collection)` pairs
- [ ] `create_index` is called only once per `(db, collection)` per process lifetime
- [ ] Subsequent `MongoCache` instances for the same collection skip the index call
- [ ] Log message only emitted when the index is actually created

## Action Log

### 2026-03-18
Added module-level `_ensured_indexes: Set[Tuple[str, str]]` in `cachetic/extensions/mongodb.py`.
`create_index` now guarded by membership check — only called once per `(db, collection)` pair.
