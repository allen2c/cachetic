# Unify backend architecture with CacheProtocol adapters

## Description

Currently DiskCache and Redis are handled inline in `Cachetic.__init__.py`
while MongoDB lives under `extensions/`. This ticket unifies all backends
behind explicit `CacheProtocol` adapter classes so that:

- Every backend is a first-class `CacheProtocol` implementation.
- `Cachetic.cache` return type becomes `CacheProtocol` (no Union of externals).
- `Cachetic.cache_url` accepts `str | pathlib.Path` — all backends
  resolved via connection strings; adapters internally reuse clients
  via module-level registries.

### URL routing (in `Cachetic.cache` property)

| Scheme prefix    | Adapter                                          |
|------------------|--------------------------------------------------|
| `redis://`       | `cachetic.extensions.redis.RedisCacheAdapter`    |
| `mongo://` etc.  | `cachetic.extensions.mongodb.MongoCache`         |
| `postgresql://`  | `cachetic.extensions.postgres.PostgresCacheAdapter` (CAC-010) |
| `pathlib.Path`   | `cachetic.extensions.disk.DiskCacheAdapter`      |
| path / other str | `cachetic.extensions.disk.DiskCacheAdapter`      |

### CacheProtocol

Positional-only parameters (`/`) so parameter-name differences across
third-party backends are irrelevant for structural subtyping:

```python
class CacheProtocol(typing.Protocol):
    def set(self, key: str, value: bytes, ex: int | None = None, /) -> None: ...
    def get(self, key: str, /) -> bytes | None: ...
    def delete(self, key: str, /) -> None: ...
```

## Completion Note

2026-04-01

Spec originally planned `cache_url: str | Path | CacheProtocol` accepting
raw third-party instances via structural subtyping. During implementation,
mypy verified that `redis.Redis` does NOT satisfy `CacheProtocol` structurally
(variadic `delete(*names)` + `Awaitable[Any] | Any` return types).

[DECISION] Simplified to `cache_url: str | Path` — all backends resolved
via connection strings. Adapters internally wrap third-party clients and
reuse them via module-level registries (same pattern as existing `MongoCache`).
This also eliminated the need for `@runtime_checkable` on CacheProtocol.
