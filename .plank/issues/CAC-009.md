# Implement Data URL serialization format with backward compat

## Description

Replace raw-bytes storage with self-describing Data URL format using `durl-py`
(`DURL.build`). Values become human-readable, explicitly typed strings.

### Write format (new default)

```
# JSON object, uncompressed (default)
data:application/json;base64,eyJuYW1lIjoiQWxpY2UiLCJhZ2UiOjMwfQ==

# JSON object, compressed with zstd
data:application/json;compression=zstd;base64,KLUv/QAATA...

# Raw bytes, uncompressed
data:application/octet-stream;base64,AQIDBA==
```

- Default: **uncompressed** Data URL (`compression=False`).
- MIME type: `application/json` for JSON-serializable types,
  `application/octet-stream` for bytes types.
- Compression metadata in DURL parameter: `compression=zstd` or
  `compression=zlib`.

### Read format (backward-compatible detection)

`_loads_any` must handle all legacy and new formats transparently:

1. Data starts with `b"data:"` → decode UTF-8, parse `DURL`, extract payload.
   If `compression` parameter present → decompress after base64 decode.
2. Data starts with compression magic bytes (zstd/zlib) → decompress, validate.
3. Otherwise → treat as raw JSON bytes (legacy format).

### Implementation in `_dump_any` / `_loads_any`

- `_dump_any` produces Data URL string, encoded to `bytes` (UTF-8) before
  passing to `CacheProtocol.set`.
- `_loads_any` accepts `bytes` from `CacheProtocol.get`, detects format,
  returns deserialized `T`.

### Backward compatibility

- All four legacy data formats remain readable forever.
- No migration needed — old data reads seamlessly, new data writes as Data URL.
- Cross-version safety: v0.6.x client reading v0.7.0 data will see a data URL
  string (graceful failure, not silent corruption).

## Acceptance Criteria

- [ ] `_dump_any` produces `data:application/json;base64,...` by default
- [ ] `_dump_any` with `compression=True` produces `data:application/json;compression=zstd;base64,...`
- [ ] `_dump_any` for bytes types produces `data:application/octet-stream;base64,...`
- [ ] `_loads_any` reads new Data URL format correctly
- [ ] `_loads_any` reads legacy raw JSON bytes (no data URL, no compression)
- [ ] `_loads_any` reads legacy compressed bytes (zstd/zlib magic, no data URL)
- [ ] `_loads_any` reads compressed Data URL format correctly
- [ ] Existing test_compression.py cross-read test still passes
- [ ] New tests cover all four read paths
